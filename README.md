## hls-project

This document provides an overview of code and artifacts used by the Harmonized Landsat Sentinel (HLS) project.  For more detailed information about the HLS product specification and distribution consult the LPDAAC [product landing page](https://lpdaac.usgs.gov/products/hlss30v002/)

The initial development goal of the HLS project was to expand existing, experimental HLS scientific algorithm code to a full scale global production pipeline running on scalable AWS infrastructure.  This document provides a map of how the code repositories used by the project are interrelated and how they interoperate.

### HLS Standard Products

The HLS standard products (S30 and L30) are surface reflectance products generated from Sentinel-2 and Landsat inputs.

#### Scientific Algorithms

The scientific algorithms used for atmospheric correction, cloud masking, BRDF correction, and bandpass harmonization. These are built and packaged for use in the HLS processing [containers](#containers).

- [lasrc-rs] - A Rust port (with Python bindings) of the LaSRC surface reflectance algorithm originally implemented in [espa-surface-reflectance].

- [espa-surface-reflectance] - The C implementation of the LaSRC surface reflectance algorithm. Depends on [espa-product-formatter].
    - [espa-product-formatter] - An ESPA metadata and format conversion utility.
    - [espa-python-library](https://github.com/NASA-IMPACT/espa-python-library) - A Python library for manipulating and validating ESPA metadata.

- [Fmask-v5](https://github.com/NASA-IMPACT/Fmask-v5) - Our maintained fork of Fmask 5, the cloud and cloud shadow detection algorithm for Landsat and Sentinel-2 imagery.

- [hls-libs](https://github.com/NASA-IMPACT/hls-science-container/tree/main/packages/hls-libs) - The HLS specific algorithms, such as BRDF correction (NBAR), bandpass harmonization, and tiling, along with other Landsat and Sentinel-2 processing steps. These live within [hls-science-container] rather than in their own repository.

#### Containers

The HLS processing pipeline runs the scientific algorithms and supporting utilities packaged as Docker containers.

- [hls-science-container] - Consolidated codebase that builds the container used to run atmospheric correction, cloud masking, and other processing of Landsat and Sentinel-2 Level-1 data to create HLS products. Builds and packages [lasrc-rs], [espa-surface-reflectance], [espa-product-formatter], and [espa-python-library](https://github.com/NASA-IMPACT/espa-python-library), and includes the utilities previously maintained in [hls-utilities].

- [hls-atmospheric-auxdata] - Builds the container that downloads and archives the atmospheric auxiliary data (VIIRS data from the LAADS DAAC and monthly climatologies) required by LaSRC. Includes a modified copy of the LAADS download script from [espa-surface-reflectance], so it no longer depends on that library.

#### Utilities

Generating HLS proudcts requires a suite of additional metadata and secondary files for ingestion into external systems such as [CMR](https://earthdata.nasa.gov/eosdis/science-system-description/eosdis-components/cmr), [Cumulus](https://nasa.github.io/cumulus/docs/cumulus-docs-readme) and [GIBS](https://earthdata.nasa.gov/eosdis/science-system-description/eosdis-components/gibs).  These Python CLI utilities are installed and used from within the containers.

- [hls-metadata](https://github.com/NASA-IMPACT/hls-metadata) - Generate CMR metadata for HLS products.

- [hls-cmr_stac](https://github.com/NASA-IMPACT/hls-cmr_stac) - Convert CMR metadata to STAC metadata for HLS products.

- [hls-browse_imagery](https://github.com/NASA-IMPACT/hls-browse_imagery) - Create GIBS browse imagery for HLS products.

- [hls-hdf_to_cog](https://github.com/NASA-IMPACT/hls-hdf_to_cog) - Convert internal HLS hdf product formats to [COGs](https://www.cogeo.org/) for distribution.

- [hls-manifest](https://github.com/NASA-IMPACT/hls-manifest) - Generate Cumulus CNM messages to be used for LPDAAC ingestion.

- [hls-thumbnails](https://github.com/NASA-IMPACT/hls-thumbnails) - Generate reduced resolution, true color thumbnails for HLS products.

- [hls-testing_data](https://github.com/NASA-IMPACT/hls-testing_data) - Not an actual utility but a suite of sample HLS products used for integration testing utilities which must read directly from the file format.

#### Static lookup files

The HLS pipeline relies on several static lookup files generated by the scientific team.  To support full process reproducibility, the code used to generate these files is openly maintained.

- [hls-L8S2overlap](https://github.com/NASA-IMPACT/hls-L8S2overlap) - Generates a lookup file of MGRS Landsat Path Row intersections clipped to the HLS data processing boundaries.

- [hls-land_tiles](https://github.com/NASA-IMPACT/hls-land_tiles) - Generates a lookup file of valid MGRS land tiles used to trim the MGRS Landsat Path Row overlap file.

#### Infrastructure and Orchestration

These repositories define the infrastructure as code and AWS components which manage the flow of data through the HLS procesing pipelines.

- [hls-orchestration](https://github.com/NASA-IMPACT/hls-orchestration) - The core HLS processing infrastructure which receives notifcations for new Sentinel-2 and Landsat data to process and generates HLS S30 and L30 products.

- [hls-sentinel2-downloader-serverless](https://github.com/NASA-IMPACT/hls-sentinel2-downloader-serverless) - Monitors new publications and continually downloads Sentinel-2 data from the [ESA International Access Hub](https://inthub.copernicus.eu/) in near real time.

- [hls-landsat-historic](https://github.com/NASA-IMPACT/hls-landsat-historic) - Sends date range listings of historical Landsat data from the USGS S3 archive to [hls-orchestration](https://github.com/NASA-IMPACT/hls-orchestration) for incremental archival processing.

- [hls-lpdaac](https://github.com/NASA-IMPACT/hls-lpdaac) - Sends HLS product CNM messages to LPDAAC's Cumulus queue to trigger ingest.

- [hls-lpdaac-reconciliation](https://github.com/NASA-IMPACT/hls-lpdaac-reconciliation) - Receives and processes reconciliation reports from LPDAAC to ensure products we request that LPDAAC publish are available to end users.

### Derived Products

These repositories generate products derived from the HLS standard products.

#### HLS-VI

The HLS-VI products provide vegetation indices computed from the HLS S30 and L30 products.

- [hls-vi] - Scripts and functions for computing HLS-VI vegetation index products from HLS bands.

- [hls-vi-historical] - Computes HLS-VI product from existing, historical HLS granules using tools from [hls-vi].

- [hls-vi-historical-orchestration] - Orchestrates running the [hls-vi-historical] container to backfill the HLS-VI product for historical time periods.

#### HLS Composites

The HLS composite products provide monthly, cloud-free composites of HLS spectral indices (NDVI, EVI, and NBR) for each MGRS tile.

- [hls-composites] - The compositing algorithm and CLI, along with tooling to orchestrate forward and historical production and to monitor granule production status.

### User Tools

These repositories contain guides, code samples, and other documentation that are intended to help users learn to use the HLS products.

- [hls-application](https://github.com/NASA-IMPACT/hls-application) - Notebooks describing how to find and use HLS products for a variety of Earth observation scenarios.

### Deprecated

Previously, each HLS component was managed in its own repository. This worked well while adapting the experimental scientific workflow into a production pipeline since each component could be developed and traced independently. Since then, we have made changes that let us manage this code more easily in one place. For example:

- we now can compile the ESPA libraries ourselves instead of relying on a pre-built base image
- we orchestrate the workflow within the container using Python rather than calling Python libraries through their CLIs
- we are reducing the number of intermediate processing steps (i.e., unnecessary format conversions), reducing the number of tools/scripts/programs required

As a result, most of these components have been consolidated into [hls-science-container] and [hls-atmospheric-auxdata], and the repositories below are no longer used for HLS processing.

- [espa-dockerfiles](https://github.com/NASA-IMPACT/espa-dockerfiles) - Provided the core library dependencies used by all of our project images. Consolidated into [hls-science-container].

- [hls-base](https://github.com/NASA-IMPACT/hls-base) - Provided the externally developed C/Python/Matlab libraries used for atmospheric correction and cloud masking, including the Matlab implementation of [Fmask 4](https://github.com/GERSL/Fmask4). Consolidated into [hls-science-container].

- [hls-sentinel](https://github.com/NASA-IMPACT/hls-sentinel) - Generated HLS S30 products from Sentinel-2 inputs. Consolidated into [hls-science-container].

- [hls-landsat](https://github.com/NASA-IMPACT/hls-landsat) - Generated intermediate surface reflectance products from Landsat inputs. Consolidated into [hls-science-container].

- [hls-landsat-tile](https://github.com/NASA-IMPACT/hls-landsat-tile) - Generated tiled HLS L30 products from intermediate surface reflectance products. Consolidated into [hls-science-container].

- [hls-laads](https://github.com/NASA-IMPACT/hls-laads) - Downloaded and synchronized required auxiliary data from the LAADS DAAC using a Python script from [espa-surface-reflectance]. Consolidated into [hls-atmospheric-auxdata].

- [hls-utilities] - Utilities used by HLS processing to read and manipulate Sentinel and Landsat product specific file formats. Consolidated into [hls-science-container].
